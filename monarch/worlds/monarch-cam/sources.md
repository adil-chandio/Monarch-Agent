# MONARCH CAM — FOOTAGE DISCOVERY, VERIFICATION, SCORING & LEDGER

This is the operating reference for pipeline Stages 2–6. The objective is to find rare,
real, story-bearing moments first—not to rescue ordinary footage with editing. A clip can be
visually excellent while its source, factual context, reuse status, or platform-risk status is
still unknown. Keep those judgements separate.

**Coverage honesty:** no search can prove that it found every clip on the internet. Run a
broad, logged, reproducible search across different source families; report what was searched
and where coverage stopped. Never claim “the whole internet was checked.”

---

The catalogs below are discovery lanes, not endorsements of every clip, metadata field, or
licence. Their live inventory, access rules, prices, and terms can change. The public catalog
page is a lead; it is not automatically a right to download or reuse a clip.

**Priority for a Monarch Cam scout:** first check Jukin, Storyful, ViralPress, CONTENTbible,
Caters, Newsflare and ViralHog; add Rumble and Collab for more breadth. Catalogues are often
better organized than a video host, but they can surface the same well-known clip across
multiple sellers. Deduplicate before treating anything as a new candidate.

### B. Native public search surfaces

Use the platforms’ own public search/browse features for YouTube, Dailymotion, TikTok,
Instagram, Facebook, X, and Reddit. Search public pages and original uploader posts. Local
news sites, wildlife agencies, national parks, trail/camera operators, and other relevant
first-party publishers are useful for context and provenance.

Dailymotion can remain a discovery source, as the operator has used it before. **A Dailymotion
page is not proof that the uploader filmed or owns the clip, nor that editing it for YouTube is
permitted.** Its current Terms (Sections 3.2 and 6.7) describe user reuse through features
within the Dailymotion service, subject to the author's settings and attribution; they do not
create a blanket off-platform YouTube licence. Section 6.7 also restricts altering third-party
videos outside Dailymotion's offered reuse features and forbids disguising/removing attribution.
Section 2.6 restricts automated access without prior written approval. Recheck the live terms
before using any platform feature or automated tool: [Dailymotion Terms of Use](https://legal.dailymotion.com/en/terms-of-use/).

Do not bypass logins, privacy settings, geographic restrictions, DRM, or paid access. Do not
bulk scrape or download where the site's terms prohibit it. YouTube's Terms restrict automated
access without written permission except for public search engines under its robots.txt rules;
Dailymotion and ViralHog also state their own automation limits above. A command being available
in Monarch does not itself grant permission to use it on a particular site. Read the live
[YouTube Terms](https://www.youtube.com/t/terms) and source terms before using automation.

## 2. REPEATABLE SEARCH METHOD

### Write the search brief before searching

For each assignment, capture:

- the channel pillar and one-sentence story question;
- the concrete visual behaviour the viewer should see;
- what would count as an exceptional payoff;
- red-line material to exclude (staged, misleading, graphic, distress-based, off-pillar);
- the number of candidate leads already reviewed and any footage already used by Monarch Cam.

Do not use a new channel-wide Analytics refresh as a prerequisite. Use the supplied channel
snapshot as context; examine fresh Studio data only when the operator supplies or asks for it.

### Query construction

Search the **action**, not just “viral,” “shocking,” or “funny.” Combine:

```
subject/species + unusual action + object/location + camera/source clue
```

Examples for a bear/door brief:

- `bear opens car door security camera`
- `bear tests vehicle handles cabin doorbell camera`
- `bear gets into parked car original video`
- `mother bear opens vehicle cubs follow`

Then vary the action, object, setting, local place names, spelling, and language. Search local
language terms for clips from other countries; verify any translated title or caption against
the footage and a source who can confirm it. Search both recent uploads and older archives,
but label a resurfaced clip as old/reused rather than “new.”

### Search passes

1. **Catalog pass:** search relevant categories and recent/featured feeds at multiple licensing
   catalogues, not just the first provider.
2. **Native-platform pass:** search the same behaviour on public social/video platforms,
   Reddit, local news, and first-party wildlife/camera-owner pages.
3. **Long-tail pass:** use synonyms, local place names, camera types, alternate spellings, and
   non-English keywords. Search for the *specific action* (opens, nudges, unlocks, slips,
   carries, returns), not only the species.
4. **Source pass:** when a moment looks promising, search its uploader name, distinctive
   caption text, visible landmarks, and several keyframes to locate earlier/longer versions.
5. **Deduplication pass:** group reposts of the same recording under one candidate ID. A dozen
   reposts are one moment, not a dozen original clips.

### Search log — required for every scout

Save to the Stage 2 section of `output/<slug>/project_notes.md` (single research file for
Stages 1–6 — not six separate reports):

| Field | Record |
|---|---|
| Scout date/time | Include timezone |
| Search lane | Catalogue / platform / local news / official source / other |
| Exact query and filters | Copy/paste the actual wording; note language and sort order |
| Results reviewed | Count only what was actually opened or inspected |
| Unique candidate IDs | Do not count reposts as separate footage |
| Shortlisted moments | Link each candidate card |
| Rejection reasons | Weak action, duplicate, off-pillar, context unclear, unsafe, etc. |
| Coverage limit | Login required, preview only, no results, search unavailable, or other limit |

Do not manufacture result counts. If a search tool fails or returns stale results, note that and
continue through another public source. Stop a search pass only after logging what was tried.
Keep searching while new, promising source families or query variants are still producing
unique candidates; do not lower the quality threshold just to finish quickly.

## 3. SOURCE, DATE, LOCATION & CONTEXT TRACE

Treat the page where a clip was discovered as the **lead page**, not automatically the original.
Trace this chain where possible:

```
lead/repost → earliest credible public upload → original filmer/rightsholder → agency/licence path
```

The earliest upload found is evidence, not proof that it is the camera-original. Record each
link and why it is believed to be upstream. A licensing agency, news publisher, uploader, and
filmer may be different parties; name their roles rather than collapsing them into “the source.”

For each shortlisted moment:

1. Watch the longest available context, not only a teaser, reaction edit, thumbnail, or title.
2. Reverse-search at least two or three distinctive frames from different points. Compare
   crops, watermarks, mirrors, subtitles, and upload dates; use results to find earlier versions,
   not to decide legal ownership automatically.
3. Check the uploader’s account history and whether they plausibly filmed it. Contacting the
   apparent filmer/source requires the operator’s explicit authorization: without it, record the
   open question instead of messaging anyone (no vendor contact, no licence request, no payment).
4. Separate **filmed date** from **posted date**. Verify the claimed location if it affects the
   narration, species, behaviour, or story.
5. Cross-check factual narration with a primary/authoritative source (e.g. wildlife agency,
   park authority, original participant, or reliable reporting). Metadata, post captions, AI
   detectors, and agency keywords can be wrong; preserve uncertainty instead of guessing.
6. Note what the footage proves and what it does **not** prove. A visible action does not
   establish motive, prior events, exact location, or what happened after the camera stopped.

If the clip cannot be traced well enough to avoid a false story, mark **SOURCE UNRESOLVED** and
do not use it as factual proof. This is an editorial trust gate, not a copyright scan.

## 4. DUPLICATES, SATURATION & MONARCH CAM NOVELTY

Keep a project-level index of candidate source URLs and clips already published by Monarch Cam.
Use canonical platform IDs/URLs where available. If an authorized file is in hand, a SHA-256
hash can identify an exact duplicate; perceptual frame/audio matches can surface re-encodes or
partial copies. Fingerprint matches prove similarity only—not who owns the work or whether use
is allowed.

Record the number of visible reposts or past Monarch Cam uses as **saturation context**:

- many reposts may mean the moment is already familiar and less valuable to this audience;
- many reposts do not prove public-domain status, permission, or that the earliest post is the
  original;
- use a familiar viral moment only when the Monarch Cam angle, verified facts, or story
  contribution is materially distinct. Otherwise reject it as overused.

Never remove, crop, blur, or replace a watermark to disguise the source or to defeat matching.
If a watermark prevents a clean, honest edit, find the source master or reject the clip.

## 5. A+ SCENE QUALITY SCORE — RIGHTS ARE A SEPARATE FIELD

Score the **actual moment**, not its headline, view count, reputation, or a vendor’s sales copy.
A preview-only score is `PROVISIONAL`; rescore from the best authorized/available source before
final edit. Score each line 0–10 and record a timestamp plus one sentence of evidence.

| # | Criterion | Ask |
|---|---|---|
| 1 | Truthful stop-scroll frame | Is real, readable action visible immediately without a misleading crop or fabricated setup? |
| 2 | Instant clarity | Can the viewer understand the subject and action in about two seconds, on a phone or TV? |
| 3 | Distinctiveness | Is this an unusual, specific behaviour/moment rather than a generic sighting or common repost? |
| 4 | Authentic emotional charge | Does the real footage create surprise, humour, awe, suspense, or concern without exploiting distress? |
| 5 | Natural escalation | Does something meaningfully change, build, or become clearer? No arbitrary cuts to fake escalation. |
| 6 | Payoff/reversal | Does the moment deliver a clear, satisfying visual result or discovery? |
| 7 | Story completeness | Is there enough context to narrate honestly, or can the missing context be verified? |
| 8 | Technical and vertical fit | Will focus, exposure, motion, resolution, and 9:16 crop preserve the action? |
| 9 | Useful natural sound/reaction | Does original sound/reaction add something? If absent, do not invent it or imply synthetic sound is real. |
| 10 | Monarch Cam fit and explanation | Does it fit one of the two pillars and give original narration a real explanatory/story job? |

### Anchors and selection rule

- `0`: no usable evidence / fatal problem; `5`: ordinary or only partly useful; `8`: strong,
  clear, story-worthy; `10`: exceptional and rare, supported by the actual footage.
- **Shortlist only if the mean is at least 8.5/10**, with criteria 1, 2, 6, and 10 each at
  least 8/10, no score below 7/10, and all factual/safety/source gates passed.
- Unknown is not a 5. If you have not inspected the footage, mark the score `PROVISIONAL` or
  `NOT SCORED`.
- No score, shortlist, or review claim without actual visual inspection. If the agent cannot play
  a clip, mark that candidate `NOT SCORED`—this blocks scoring that candidate only, not Stage 4 or
  the pipeline. Try another permitted, viewable candidate or an authorized local file/player;
  only after those alternatives fail ask once for an accessible upload/source. Never invent scores.
- Never write scene-specific script/VO/EDL from unseen footage, and never present an EDL with
  `TBD` timecodes as a complete edit.
- The scores are evidence-backed editorial judgements, not a claim that the clip will go viral.
- If nothing passes, keep searching or report “no A+ candidate found.” **Do not promote a weak
  clip, pad with filler, or edit it to look more dramatic than it is.**

### Hard editorial rejects (score cannot override)

- fabricated, AI-generated-as-real, materially miscaptioned, staged distress/rescue, or
  unresolved source/context that makes the story unreliable;
- graphic harm, animal cruelty, or shock/disgust used as the main attraction;
- a clip outside the two channel pillars with no honest Monarch Cam connection;
- action unreadable after the intended crop or no meaningful visual payoff;
- a title/story that depends on claiming an “attack,” motive, location, or danger not supported
  by evidence;
- a duplicate of a recent Monarch Cam asset with no genuinely new story contribution.

## 6. CANDIDATE CARD & DECISION STATUSES

For each lead, record one compact candidate card before the approval gate:

```text
Scene ID:
What the camera visibly shows (one sentence):
Lead page / platform / item ID:
Earliest credible upload found:
Original filmer/rightsholder (role and evidence):
Filmed date / place (confirmed, inferred, or unknown):
Duration / resolution / audio / vertical-crop notes:
Other copies / saturation note:
Pillar + intended story question:
Quality score (provisional/final) + timestamps/evidence:
Safety/context decision:
Rights status (separate from score):
Copyright-risk screen status (see claim-risk.md):
Attribution / licence evidence / unresolved questions:
Decision + exact reason:
```

Use only these workflow labels; never use “copyright-free” based only on an automated no-match:

- `FOUND` — public lead located; no claim about rights or source yet.
- `DUPLICATE/OVERUSED` — same recording already widely reused or already used by Monarch Cam.
- `SOURCE UNRESOLVED` — original/context cannot be established enough for truthful storytelling.
- `PROVISIONAL SCORE` — only a public preview was available.
- `MATCH FOUND` — a tool/platform reports a possible reference match; investigate the segment.
- `NO MATCH FOUND` — no match in the checked database/tools only; **not** proof of permission or
  future claim safety.
- `RIGHTS DOCUMENTED` — written terms/evidence were inspected for the specified use.
- `RIGHTS UNKNOWN` / `REVIEW REQUIRED` — rights were not established; do not relabel as clear.
- `REJECTED` / `SHORTLISTED` / `OPERATOR APPROVED WITH RISK NOTED` — record who made the final
  decision and when.

`OPERATOR APPROVED WITH RISK NOTED` is written only when the operator explicitly acknowledges a
**named** risk. “Aage barho/continue” does not set it — that phrase approves only the current
creative gate (never missing intake, unchosen options, rights approval, vendor contact, or
publication permission).

The assistant never signs a licence, makes a legal determination, or says a clip is guaranteed
claim-free. Analysis and planning may continue while rights are unknown, but the status stays
`RIGHTS UNKNOWN` until evidence exists, and no vendor contact, licence request, or payment happens
without explicit operator authorization. See `claim-risk.md` for the one-minute screen and
YouTube pre-publish check.

## 7. STAGE 6 — STORYLINE, NOT MONTAGE

Build one coherent spine from verified visual beats. Each scene must add a new fact, attempt,
reaction, reveal, or payoff. If deleting a beat does not weaken the story, delete it. If the
clips do not genuinely belong to one event, do not edit them to imply they do.

For the bear/door brief, a possible spine is:

```
Approach → tests access point → enters vehicle/home → human/cub reaction → sourced explanation
```

It is a hypothesis until the selected footage proves it. The end should pay off the opening
question or leave a truthful next question; it does **not** have to be bigger, louder, more
violent, or more shocking than the opening.

Gate A waits for operator approval of the actual candidate cards, score evidence, story spine,
source/context confidence, and claim-risk labels — for candidates that were actually visually
inspected. A link list alone does not pass the gate. Ask only this gate's question: destination
URL, editor, VO, and disclosure questions belong to later stages and are not batched here; a
missing destination URL is not an early blocker.
