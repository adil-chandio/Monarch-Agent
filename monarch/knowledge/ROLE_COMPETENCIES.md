# Role competencies and manager-led operating structure

**Purpose:** strengthen Monarch's existing roles without replacing their cards or creating an unnecessary swarm of always-on agents. Roles below are capabilities; the Manager activates only the specialists required for the task.

## Central manager

### Manager / Executive Producer — run owner

- **Owns:** the brief, approved goal, schedule, routing, current stage/status, dependencies, evidence completeness, revision requests and final reconciliation.
- **Must know:** the selected world and constitution; the requested style; artifact dependencies; source/evidence labels; current tool limits; which decisions remain operator-gated.
- **Must deliver:** a job card; a visible stage/status ledger; one accountable owner per artifact; evidence-based revision notes; a release checklist whose claims point to real files and test results.
- **Must not:** choose a gated topic/idea/voice/title for the operator; infer private competitor analytics; waive rights, HAAN, approval, QA or human-upload law; report an intended action as completed.

Manager handoff summary for each stage: `stage · owner · status · artifact · evidence · checks · blocker · next owner`. A specialist returns its result to the Manager, not as an untracked parallel narrative. Creative approval and WAIT behavior remain exactly as defined by the active workflow.

## Manager-controlled workflow

1. **Intake and route:** preserve existing access, workflow selection and intake; record approved goal, channel/world, ratio, duration, language and requested visual style.
2. **Research and concept:** Scout returns a sourced dossier; Manager routes selected idea candidates through existing gates. Keep facts, observed evidence, hypotheses and unknowns separate.
3. **Script and claim review:** Script Doctor hands off claim IDs and payoff map; independent reviewer checks material facts and rights before the next production gate.
4. **Preproduction:** visual/audio roles receive the locked brief, timing and canonical style references; QA checks plans before rendering when appropriate.
5. **Render and independent review:** inspect the actual encoded file, not only a plan. Run objective checks, inspect contact sheets and compare the delivered media to the approved script/plan. No full-video watch by the operator is required for routine QA, but this does not remove the existing `HAAN`, `WAIT`, creative-approval, rights or publication gates.
6. **Learn:** ingest only authorized data; compare against a relevant channel/format baseline; log a future hypothesis instead of turning one result into a permanent law.

## Shared output quality bar

- Each asset has a clear purpose and owner; handoffs include source IDs and exact artifact paths.
- Unsupported factual claims, unknown rights, hallucinated metrics, unexplained tool failures and missing required deliverables remain visible.
- A reviewer reports independent evidence; creative preference is identified as preference, not measurement.
- If any required gate is failed or unmeasured, return a specific fix to the Manager and keep the work blocked.
